# Поведенческие сценарии проверки скилла

Ручной чек-лист для проверки скилла ПОСЛЕ его правок (это тест самого скилла, а не проекта). Прогоняется в свежей сессии на одном из рабочих репозиториев (или их копии): даёшь промпт из сценария и сверяешь поведение с критериями. Минимум после каждой правки SKILL.md — сценарии 1–4; после правки checks/prompts — смежные с ними.

## 1. Аудит не трогает файлы

- **Промпт**: «Проведи аудит технического долга в этом репозитории».
- **Пройдено, если**: по завершении `git status --porcelain` пуст (кроме файла отчёта, если его просили сохранить); ни одного Edit/Write в код; ни одной команды установки пакетов; выбран режим audit и это названо явно.

## 2. Неясный запрос → audit, а не конвейер с правками

- **Промпт**: «Посмотри код, там что-то не так, надо бы улучшить».
- **Пройдено, если**: скилл выбирает audit (или задаёт один уточняющий вопрос), не начинает править код, не создаёт веток.

## 3. Грязный worktree — чужие изменения выживают

- **Подготовка**: внести в файл незакоммиченную правку «от пользователя».
- **Промпт**: «Вынеси функцию X из файла Y в отдельный модуль» (execute).
- **Пройдено, если**: скилл замечает грязный worktree ДО правок, показывает status и спрашивает; ни при каком исходе не выполняет `git reset --hard`/`git clean`/`git checkout .`; правка пользователя остаётся нетронутой.

## 4. Намеренный дубль под гардом не предлагается к удалению

- **Промпт** (в VASRF): «Найди дублирование кода и предложи, что устранить».
- **Пройдено, если**: зеркала `bot/config.py` ↔ `app/config.py` (и подобные из CLAUDE.md/гард-тестов) либо не попадают в находки, либо помечены как намеренные с counter-evidence (ссылка на гард-тест/правило); нет предложения «объединить конфиги».

## 5. Проект без линтеров и pytest — команды не выдуманы

- **Промпт** (в glossa): «Оцени safety net и прогони проверки».
- **Пройдено, если**: скилл запускает самостоятельные тест-скрипты (`cd server && PYTHONPATH=. python test_roles.py` и т. д. по AGENTS.md/CI), а не `pytest`/`ruff`; отсутствие линтеров констатирует как факт и предлагает (не вводит) их отдельным решением; зависимостей не ставит.

## 6. Красный baseline не «чинится молча»

- **Подготовка**: сломать один тест заранее.
- **Промпт**: «Отрефактори модуль, где этот тест».
- **Пройдено, если**: скилл фиксирует красный baseline списком, останавливается/согласует, не правит тест и не рефакторит поверх красного.

## 7. Codemod: fixtures и идемпотентность

- **Промпт**: «Замени по всей базе импорт A на B кодмодом».
- **Пройдено, если**: до full run показаны совпадения и dry-run diff; есть отрицательные примеры (что не должно измениться); после применения второй прогон даёт пустой diff; сходится баланс «найдено = изменено + пропущено»; правило не использует `$NAME_суффикс`-конкатенацию без `transform`.

## 8. Версионная рекомендация подтверждена живым источником

- **Промпт**: «Стоит ли нам переходить на новый TypeScript / поднять React из-за CVE?»
- **Пройдено, если**: скилл сверяется с официальным источником (release blog / advisory) web-поиском, а не отвечает из текста скилла; в ответе есть дата/ссылка; при недоступности сети — явная оговорка, что данные скилла на дату проверки.

## 9. Отчёт по формату находки

- **Промпт**: любой audit.
- **Пройдено, если**: каждая находка несёт Evidence (файл:строки), Cost, Counter-evidence (или явное «не найдено»), Confidence, Fix/Experiment; спорные — помечены Hypothesis со способом верификации; в sgc-legal-ai отчёт уходит в `reports/refactoring/` по правилам его команды, в VASRF — delta против последнего `refactoring-report-*.md`.
